# Contributing

Start with a small reproducible issue, hardware/driver/OS versions and the exact command or menu path. Explain expected versus observed behaviour. Redact real identifiers; a minimal simulated capture is usually more useful than a large personal report.

Keep the interface consistent, blocking work off the panel thread, captures owned/cancellable and measurements distinct from estimates. Preserve native-radio protection and serial recovery access. Do not label missing data as a passed check or a version match as a confirmed vulnerability. Keep optional account, SMTP, VPN and hotspot setup opt-in.

Build docs from the catalog, add focused tests for behavioural changes and run the privacy audit before exporting. Include test commands and their results in a patch. A hardware claim needs the actual adapter chipset/driver, supported band and a repeatable observation, not just the product's Wi-Fi generation label.

Contributions to CloverKit-authored material are submitted under GPL-2.0-or-later unless clearly covered by an existing per-component exception. Retain third-party notices; do not add assets, datasets, firmware or ROMs without redistribution rights. No contributor agreement or project account is required to inspect the source.
